A probe's signature is the kind of probe without the probed address (for example Invalid URL or HTTP 404 via GET), so a scanner trying a thousand paths stays one line in the summary; the address it tried is in the Target and Path columns. Everything a caller chose (paths, User-Agents, header names and values, CSP report fields) is shown as plain text, exactly as stored and with secrets already removed.

Fingerprints count what callers send when they pass every check. A header whose values change on almost every request (a trace id) is marked high cardinality: stop recording its values in its details and only its count is kept. The Blocked tab lists what requests refused by a {{ term("request-filter", "request filter") }} carried, so a filter that catches real callers by mistake shows up.

Your sessions, trusted devices, passkeys and recovery codes are yours alone. Ending a session signs that browser out at once; a trusted device skips only the second factor, never the password. Renaming or deleting a passkey and making new recovery codes ask for your second factor again first.
