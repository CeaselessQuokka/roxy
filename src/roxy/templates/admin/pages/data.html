Sizes are measured from the database files themselves; the 30 day projection uses the rows added over the last week, bounded by each table's age and row limits. The measured growth comes from samples the leader takes every hour, so it shows what really happened, not an estimate.

Before a reset deletes rows, Roxy copies the affected database into a snapshot (kept for the days and within the space the retention settings allow), writes the exact rows per table to the {{ term("audit-log", "audit log") }}, and leaves a {{ term("annotation", "marker") }} on every chart covering that time, so a number that dropped never looks like real traffic going away.

Back up now asks the server's nightly backup to run at once (it compresses, checks and can copy the backup off the server) and also keeps a copy here when one fits. Exports leave Roxy: client addresses in them are replaced by keyed hashes unless you turn on including them below, and every download is written to the audit log first.
