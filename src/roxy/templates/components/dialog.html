{#- Confirm dialog with plain-language consequences and type-to-confirm (plan 14.5). What `confirm_dialog("dlg-purge", "Purge the whole cache?", action="/admin/api/v1/cache/purge", danger=True, consequences=[...], type_to_confirm="purge", api=True)` renders a native . Open it with any button carrying `data-dialog-open="dlg-purge"`; static/js/dialog.js opens it as a modal, traps focus (the browser does that for modal dialogs), closes on Escape or Cancel, and gives focus back to the button that opened it. Why A destructive action deserves one deliberate pause that says what will happen in plain words. Typing a word (type-to-confirm) is reserved for actions that cannot be undone, so it never becomes a habit people click through. A reason field feeds the audit log (plan 9.7). How API mode (`api=True`, every dashboard page): the form sends JSON to the admin API (`data-api-form`; the URL is `action`, the method `method`), built by static/js/api_forms.js from the fields: a field's `data-json` says its type (`bool`, `int`, `float`, `string`, `skip-empty`), a checkbox is a boolean, `confirm_text` (type to confirm) is never sent. The X-CSRF-Token header is added; 403 `reauth_required` asks for the second factor and retries; 422 shows each field's message under it (`confirmation_required` reveals the field marked `data-confirm-field`); other errors show in the dialog. On success the dialog closes, a toast says `success` (or the answer's message) and `on_success` decides what follows: `reload` the page, `refresh` the cards named in `refresh` (static/js/cards.js), or nothing. Form mode (the development gallery; `api=False`): the form posts with htmx (`hx-post`, or another method), so the X-CSRF-Token header is added by static/js/htmx_setup.js; a 2xx closes the dialog, an error stays in it. Either way the confirm button stays disabled until the typed text matches, through the `typeConfirm` Alpine component (static/js/components.js). When the API checks the typed phrase itself (a data reset's `confirm`, a VACUUM's), `confirm_field` names the field the typed text is sent as; without it the typed text is never sent. Never put the phrase in `hidden` instead: the API's own check would then pass without anyone typing it.
