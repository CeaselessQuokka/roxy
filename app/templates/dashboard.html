Response Cache

Off 0 requests saved

What this does

When two callers ask the same question, ask Roblox once and give both of them the same answer. That is the whole idea.

It is the only control on this page that is not based on who is asking, which is why it reaches traffic the others cannot. A Roblox game contacts you from hundreds of different server IPs, so every per-IP rate limit sees a brand-new caller and waves it through. Roblox, on its side, sees one proxy asking the same question hundreds of times — and rate-limits you for it. Answering the repeats yourself is the only part of that you control.

The words used on this page

Hit
We already had the answer and handed over our copy. Roblox never heard about this request.
Miss
We did not have it, so we asked Roblox, passed the answer on, and kept a copy for next time. This is the one that costs you a request to Roblox.
TTL
Short for time to live — how long a saved answer counts as current. With a TTL of 60 seconds, the first person to ask sends one request to Roblox and everyone asking in the next minute gets that same saved copy.
Expired
A saved answer whose TTL has run out. We no longer treat it as current, so the next person to ask sends us back to Roblox for a fresh one.
Stale
An expired answer that we handed over anyway, because the fresh request to Roblox failed. A slightly out-of-date number beats an error — see Serve stale for below.
Entry
One saved answer, for one exact question. ?universeIds=123 and ?universeIds=456 are two different questions, so two entries.
Evicted
Thrown out early — before its TTL ran out — because the cache had hit its size limit and needed the room.
Purge
Delete a saved answer on purpose, right now. The next person to ask for it goes to Roblox.

Throttle Rules

Escalation off 0 client rules

What this does

The plain per-IP limit treats every offender the same: go too fast, wait a few seconds, carry on. For someone who is merely quick that is exactly right. For a bot that trips the limit every single window, it teaches the wrong lesson — that waiting it out works.

So each throttle is a strike, and the ladder below decides what the next one costs. A multiplier stretches the wait; the message is what that caller is told, which is the part that actually changes anything — the author of a scraper reads the error body, not the status code.

Underneath, client rules solve a different problem: a bot that is not malicious enough to block but is not respecting the limits either. Match it by its User-Agent and give it a lane of its own — a burst allowance, or a fixed gap between requests — with a message written for that specific bot.

The words used on this page

Strike
One throttle earned. The count is what decides how hard the next one is, so it is what makes a repeat offender different from someone who was briefly fast.
Rung
One step of the ladder. Rung 1 applies to a caller's first strike, rung 2 to their second, and so on. Past the last rung, the last rung repeats.
Multiplier
How much longer that rung's timeout is than the normal one. With a 50-second default, ×4 means a 200-second wait.
Decay
Strikes fade with good behavior. After the quiet period set below, a caller drops one rung — so a single bad afternoon does not follow them forever.
Burst
A client rule shape: N requests per P seconds. Right for a scraper that works in batches and then sleeps.
Cooldown
The other shape: a minimum gap between requests. Right for a bot that hammers steadily — it turns "as fast as I can" into a fixed, predictable rate.

Endpoint Controls

Blocked Endpoints

Blocked endpoints return an error to everyone in real-time. Use a full path (games.roblox.com/v1/games) to block it and everything under it, or just a host (games.roblox.com) to block the whole service. Use * as a wildcard for one path segment: games.roblox.com/v1/games/*/servers blocks servers for any game but leaves /votes alone. Switch the type to Regex for a full regular expression, e.g. games\.roblox\.com/v1/games/\d+/servers.

Tarpit (slow refusals)

Off

When a request is going to be refused anyway, hold the connection open for a while before answering. A synchronous client — which most exploit HTTP wrappers are — can't send its next request until this one returns, so the hold acts as a rate limiter: instead of hammering us in a retry loop against an instant 429, they manage one attempt per hold. The caller receives the byte-identical error they always did, just later — nothing in the response reveals the delay.

The thing to watch is “Skipped”. A held request occupies one gunicorn worker thread for its whole hold, and there are only thread for its whole hold, and there are only workers × threads of those (16 by default). The concurrency cap below is what stops the tarpit starving real traffic: past it, callers get refused instantly exactly as before. If Skipped is climbing, the cap — not the exploiter — is the limit.

IPs on the Throttle Bypass list are never held, so you can always test against your own server.

Each hold is a random length in that range — a fixed delay is learnable, so a client could just set a shorter timeout and never wait. Capped at 55s so a hold can never outlive the gunicorn worker timeout (90s), which would kill the worker instead of the caller.

A held request occupies one of the fleet's request slots for its whole hold, so Max concurrent is clamped to a share of the real slot count — set it higher than the fleet can afford and the extra is quietly ignored rather than starving real traffic.

Request Filters (Header Blocking)

Deny requests by their headers — useful for blocking exploit tooling that tags its traffic (e.g. a Xeno-Fingerprint header, or a User-Agent containing Xeno). Blocked callers get a normal-looking throttle response (429), so they think they're rate-limited rather than filtered. Matching is case-insensitive, and every blocked request is recorded under Blocked Request Fingerprints below so you can check for false positives.

  • Specific header (most precise — fewest false positives): fill the Header box (e.g. User-Agent) to match only that header's value.
  • Otherwise Match against applies: Header name (the key), Header value (any value), or Name or value (either).

A filtered caller normally receives the ordinary throttle 429, so they conclude they are sending too much rather than that they have been fingerprinted. Setting a reply tells them they were caught — useful for redirecting a legitimate integration, a gift to a hostile one.

Workers

Every gunicorn worker currently serving traffic. gunicorn recycles a worker once it has served 2000 requests, so their ages differ by design — that's what made a single “worker uptime” reading jump around. A worker whose memory climbs while the others stay flat is the one worth looking at.

All Requests counts everything a worker served — including this dashboard polling itself every few seconds — because that is the set gunicorn counts toward recycling. Proxy Requests counts only traffic aimed at the proxy. If the first is climbing and the second is not, the only thing talking to this server is you: the proxy is idle, not broken.

Internal Requests
